# Контекст проекта 3ANT Marketing Agency

Этот файл нужен для следующего чата с Codex. Если работа продолжается в новом диалоге, сначала прочитай этот документ, затем изучи файлы проекта и только после этого вноси изменения.

## Что это за проект

Проект — главная страница сайта marketing / digital-агентства `3ANT.`.

Позиционирование:

- агентство строит не разрозненные услуги, а единую digital-систему роста бизнеса;
- система объединяет сайт, рекламу, SEO, аналитику, CRM, автоматизацию и развитие;
- визуальный стиль: premium business-tech, SaaS-style landing, dark UI, calm digital, системность, дорогой минимализм.

Нельзя уводить дизайн в:

- кислотный cyberpunk;
- хаотичное креативное агентство;
- NFT / gaming / neon-overload стиль;
- перегруженные карточки и случайные декоративные элементы.

## Технологии

- Next.js
- React
- TypeScript
- CSS Modules
- Анимации в основном через CSS

## Секции и текущие решения

### Header и Hero

Hero — тёмный premium business-tech экран:

- логотип `3ANT.`;
- descriptor: `Системный маркетинг для бизнеса`;
- крупный заголовок: `Строим систему роста для бизнеса`;
- справа кодовый dashboard visual;
- графики анимированы;
- кнопки со спокойными hover-состояниями.

Плашка `СИСТЕМНЫЙ МАРКЕТИНГ` является визуальным эталоном для section eyebrow / label.

### TrustLogos

Секция «НАМ ДОВЕРЯЮТ»:

- текстовые логотипы в едином приглушённом стиле;
- строка медленно движется;
- должно быть много воздуха между названиями компаний.

### BusinessValueSection

Блок «Что получает бизнес»:

- слева заголовок `Digital-система, а не набор услуг`;
- справа кодовый visual с dark glass motherboard / system board;
- ниже 6 карточек преимуществ.

Важно для visual:

- модули и иконки не должны слипаться;
- линии должны приходить в центр иконок;
- лишние линии, которые никуда не приходят, лучше убрать;
- должно быть ощущение единой digital-системы.

### CasesSection

Блок «Наши кейсы»:

- три кейса: `Bogov Team`, `ОборонСпецСплав`, `Металлобаза Волхонка`;
- порядок не менять;
- третий кейс светлый;
- внутри mockup используются PNG из `public/cases`;
- не генерировать UI кодом внутри устройств.

Теги сейчас сокращены до трёх в каждом кейсе, чтобы не было лишних переносов.

Eyebrow должен быть `НАШИ КЕЙСЫ` и совпадать по размеру с плашками других секций.

### ProcessSection

Блок «Как строится digital-система»:

- 5 этапов;
- волнообразная SVG-линия без стрелок;
- точки-узлы 01–05;
- частицы вокруг линии должны быть хаотичными, не линейным паттерном;
- карточки этапов одинаковой высоты на desktop;
- нижние result-плашки внутри карточек должны быть компактными, максимум около двух строк.

Нельзя использовать пазл и ракету в иконках процесса. Для запуска / интеграций используется ring icon.

### ServicesSection

Блок «Услуги»:

- слева текст и orbit visual;
- справа 6 карточек услуг;
- в центре визуала не должно быть плоской сферы / некрасивого круга с платой;
- оставлены орбиты, иконки и центральное свечение;
- hover карточек — мягкий цветной blur сверху вниз, не лазерная линия.

Карточка 06 была переименована в `Рост digital-системы`, чтобы слово `масштабирование` не упиралось в край.

### WhyUsSection

Блок «Почему с нами работают»:

- правый готовый image visual был убран, потому что не понравился;
- вместо него кодовый анимированный visual с орбитами и иконками;
- центральные синие квадраты были убраны;
- карточки 3x2;
- нижняя плашка со статичными метриками `90+`, `80%`, `100%`.

Важно: пользователь просил вернуть эти метрики статичными, без count-up.

### ResultsSection

Блок «Результаты в цифрах»:

- editorial layout, не карточки;
- цифры `50+` и `68+` крупные, вертикально друг под другом;
- эти цифры должны оставаться большими;
- заголовок:
  - `Системный подход`
  - `Измеримый результат`
- без точек в конце строк заголовка;
- справа 3 тезиса:
  - `Системный подход`
  - `Прозрачная аналитика`
  - `Рост через данные`
- у `Рост через данные` запятая была убрана;
- линии должны приходить в центр круглых иконок;
- hover иконок должен быть в фиолетовой гамме, не зелёной.

### TechnologiesSection

Последний добавленный блок:

- идет после `ResultsSection`;
- слева eyebrow, заголовок, описание, 3 вертикальные метрики;
- справа Digital Core-схема с 6 модулями;
- не делать нижнюю плашку, в референсе её нет;
- все модули должны помещаться в контейнер, не уходить вправо;
- схема не должна создавать горизонтальный скролл.

Текущая задача по этому блоку уже частично решена: схема ужата до контролируемой ширины, карточки и Digital Core стали компактнее.

## Типографика и текстовые правила

Очень важное требование пользователя: убрать висячие предлоги и союзы.

Использовать неразрывные пробелы:

- `и&nbsp;`
- `а&nbsp;`
- `в&nbsp;`
- `на&nbsp;`
- `с&nbsp;`
- `к&nbsp;`
- `за&nbsp;`

В TypeScript-строках часто используется `\u00a0`.

Особенно проверять:

- заголовки карточек;
- подписи под цифрами;
- короткие описания в карточках;
- строки с `и`, `а`, `в`, `на`, `с`, `к`.

Текст не должен касаться краёв карточек / фреймов.

## Общие дизайн-правила

Сохранять:

- dark premium background;
- deep navy / graphite / near-black;
- blue / violet / cyan accents;
- glassmorphism;
- мягкие glow-эффекты;
- строгую сетку;
- много воздуха;
- спокойные, дорогие анимации.

Не делать:

- кислотный neon;
- резкие анимации;
- слишком яркие blur-пятна;
- случайные декоративные элементы;
- перегруз карточками;
- горизонтальный скролл.

Анимации:

- opacity + translateY при появлении;
- медленные glow / pulse;
- SVG stroke animation для линий;
- hover должен быть subtle.

## Адаптив

Всегда проверять:

- desktop 1440px;
- laptop 1280px;
- tablet 1024px;
- mobile около 390px.

На mobile:

- не должно быть горизонтального скролла;
- сложные схемы должны перестраиваться в колонку или сетку;
- absolute desktop-композиции нельзя оставлять огромными;
- текст не должен упираться в края.
